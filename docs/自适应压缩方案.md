# 自适应压缩方案（跨度驱动）

## 概要

把压缩从「固定阈值」改为「按素材自身起伏反推参数」：不预设阈值，先量出这段录音的动态跨度（P90 − P10），再由档位目标跨度反推压缩比与阈值。

**要解决的问题**：口播录制的麦克风增益没人管得住——有时拧得很小、有时拧得很大。固定阈值（0.1.45 的 −28 / −32 / −36 dBFS）只对某一档增益有效，增益一漂，要么压空、要么压不动，用户只能反复试档位。

**关键点**：跨度是相对量。增益整体平移，P10 与 P90 同步平移，差值不变。所以「拧大拧小都不影响判定」是被数学保证的，不是靠调参凑出来的。

改动全部在前端，不涉及 Rust。落点：[compression.ts](../src/utils/compression.ts)、[App.tsx](../src/App.tsx)，同步 CONTEXT.md / AGENTS.md / README.md 三份文档。

> 0.1.49 起这条流水线扩成了**语音优化链**（高通 80 Hz → 向下扩展 → 软拐点压缩 → 响度标准化），并删掉了「按最深处补偿」。跨度驱动的口径仍然成立，本文的第三步、第四步与「保持不变的部分」已按新链路改写。

---

## 问题背景

0.1.43 的第一版压缩之所以「像没起作用」，根因是检测器跟踪峰值包络，而语音的峰值比有效值高 8 ~ 12 dB：

* 阈值照着用户期望的峰值区间（−12 ~ −6 dBFS）设，也就是 −14 / −18 / −22。
* 用户说话时的**有效电平**却在 −22 ~ −30 dBFS。
* 两者错位 8 ~ 10 dB → 只有偶发尖峰被咬到，整段起伏纹丝不动。

0.1.45 把检测器换成真 RMS 的一阶指数平滑（30 ms）、阈值下移到 −28 / −32 / −36，读数对上了，但**固定阈值本身仍然是脆的**：它假定用户的输入增益落在一个预设好的区间里。事实不是。

---

## 方案

### 第一步：量起伏（先剔气口）

1. 只按**保留区间**逐 100 ms 算短时 RMS，得到一串「块电平」（与响度测量同口径，切掉的区间不参与）。
2. 取**全部块电平的 P10** 作**噪声底**。
3. 剔除低于「**噪声底 + 14 dB**」的块——这些是气口与停顿。
4. 剩下的块取 P10 与 P90，**输入跨度 = P90 − P10**（dB）。噪声底另供扩展器定阈值。

剔除门限**锚在噪声底上，不锚在中位数上**（0.1.60 改）。锚中位数有两个必炸的后果：① 中位数会随压缩移动，而压缩就是这条链的一环 —— 压缩把语音压低十几 dB → 中位数下降 → 门限跟着下降 → 原本被剔掉的气口重新进入统计，实测「输出跨度」反而比输入更大（0.1.60 实测出现过「跨度 19.2 dB → 24.5 dB」）；② 中等信噪比素材上气口只比中位数低约 19 dB，落不进「中位数 − 20 dB」的门限，气口于是被算成语音，**P10 直接变成气口电平** → 压缩阈值落在气口上、压缩比顶到 4:1，同时扩展器因 headroom ≈ 0 而永久跳过。噪声底是气口的电平，压缩在气口处增益≈0，不随压缩移动；它同时是绝对量，麦克风增益整体平移时同步平移、门限跟着平移，判定不变。门限另外夹在「中位数」以下，防止没有气口的连续说话素材把一半动态当成噪声切掉。**量压缩输出时也要把「输入的」噪声底当锚传进去**，前后才是同一批块。

统计只算保留区间：早先含已切除区间，切掉一段响噪音会把 P90 撑大、压缩比高估，对成片压过头。

### 第二步：按档位反推参数

档位只回答一个问题——「想压到多窄」。

| 档位 | 目标跨度 | 起音 / 释放 |
| --- | --- | --- |
| 轻 | 8 dB | 20 / 250 ms |
| 中 | 5 dB | 15 / 200 ms |
| 强 | 3 dB | 10 / 150 ms |

反推公式：

* 需要压掉的量 = 输入跨度 − 目标跨度
* **压缩比 ≈ 输入跨度 ÷ 目标跨度**（封顶 4:1）
* **阈值取在 P10 附近**（配 6 dB 软拐点），让最低的有效段基本不动，只压大的

推导依据：阈值之上的动态范围会按 1 / ratio 收缩，所以要把跨度 S 映射到目标 T，需要 ratio ≈ S / T。阈值设在 P10 时，P10 以下不动、P90 落到「阈值 + T」，新跨度正好接近 T。

**举例**：某段口播跨度 12.4 dB，选「中」（目标 5 dB）→ 压缩比 2.5:1、阈值约 −31 dBFS。

### 第三步：处理链（0.1.49 起）

高通 80 Hz → 向下扩展（阈值 = `min(噪声底 + 6, P10 − 3)` dB，2:1、最多 12 dB）→ 软拐点压缩（真 RMS 检测器）→ **响度标准化**（含全链唯一一次真峰值限幅，复用 [lufs.ts](../src/utils/lufs.ts) 的 `renderLimited`）。

* **高通**：80 Hz 二阶 Butterworth，削掉隆隆声、桌面震动与近讲低频堆积。线性滤波，不产生谐波。
* **向下扩展**：在停顿与气口处按住底噪，避免归一抬响度时把底噪一起抬起来。用向下扩展而不是硬门（硬门切气口很难听）。两条自动跳过规则：底噪比语音有效电平低 30 dB 以上（信噪比已经够好）不做；噪声底与语音挨得太近、阈值夹不出余量也不做 —— 做错比不做更糟。
* **扩展器阈值必须夹在噪声底与语音 P10 之间，至少低于 P10 3 dB**：压缩阈值就是 P10，扩展器一旦啃进语音最轻段，压缩量出的 P10 就成了假值，跨度自适应会自我打架。两个模块共用同一份统计（`SourceLevels`）。
* **不补偿，压缩段也不限幅**：「按最深处补偿」是静态抬全段、抬完由限幅器收拾，波形必然变平顶香肠；更关键的是末尾归一按实测 LUFS 重算增益，会把这份补偿在数学上抵消 —— 收益归零，限幅留下的增益包络却不可逆。全链限幅只允许出现一次，就在归一里。
* 时间常数分开：扩展器 10 ms 检测 + 8 ms 张开 + 250 ms 合拢（张开慢了会吃词头），压缩器 30 ms 检测 + 档位起音/释放。

最后那步归一属于链路的固有环节（0.1.48 用户要求）：链路只把动态压平、把音色修顺，不负责把整体响度拉到目标，分两步点用户容易漏，所以点一次「压缩」直接做到位。「响度标准化」按钮本身仍是单纯归一、行为不变，需要单独调响度时仍用它。

撤销是两级的：「撤销压缩」整体回退到链路之前（含链路里那次归一），「撤销响度」只退归一那一步、保留链路结果。

ceiling 口径与响度归一一致：WAV −1 dBTP / MP3 −1.5 dBTP。

### 第四步：播报（说人话）

播报里必须给出链路各步、实测跨度与由此生成的阈值与压缩比，让用户能看懂「为什么是这个数」：

> 已做语音优化：高通 80 Hz · 扩展底噪（阈值 −52 dBFS、最多 12 dB）· 已按「中」档压缩（跨度 12.4 dB → 5.2 dB，阈值 −31 dBFS、压缩比 2.5:1）
> 成片有效电平 −29.1 dBFS · 平均压掉 4.6 dB
> 响度 −27.4 → −19.0 LUFS（目标 −19）· 最终真峰值 −1.0 dBTP（上限 −1）· 限幅衰减 0.0 dB

**不再播报「自动补偿 +X dB」**：压缩后峰值与最终真峰值两个数字并排会互相拆台，用户读到的是承诺 → 违约。峰值有没有变小，看「最终真峰值 + 限幅衰减」这两个数就够。

### 边界策略（全部如实播报，不假装）

* **压缩比顶到 4:1 仍压不够** → 播报「已到压缩比上限，实际压到 X dB」。
* **素材本来就比目标还稳**（可压量不到 1 dB）→ 压缩这一步不动音频，但链路仍继续做响度标准化，播报「这段本来就很稳，无需压缩」。
* **素材太短**（剔除气口后有效块不足约 2 秒）→ 退回兜底「阈值 = 成片有效电平 − 3 dB、压缩比 2:1」。
* **底噪已经够干净 / 阈值夹不出余量** → 扩展这一步跳过，播报说明原因。

## 保持不变的部分

* **替换式语义**：换档位再点 = 从基准重算，不会叠压；`compressBaseRef` 在新录音 / 导入 / 恢复原始 / 确认降噪时清空。
* **反向依赖**：链路改了动态，此前单独做过的那次响度归一动工作废，按 `loudnessBaseRef` 回退后自动重算 —— **不再提示用户「请重新点一次」**（0.1.48 前的旧文案）。
* **撤销压缩**、AB 对照、`CompressionResult` 的 `averageReductionDb` 语义不变；0.1.49 起 `makeupDb` / `limiterGainReductionDb` / `truePeakDb` 随补偿与压缩段限幅一起删除，改为 `outputSpanDb`（实测输出跨度）。
* **档位标签**仍是「轻 / 中 / 强」，tooltip 里写清目标跨度。
* **不保留「手动固定阈值」档**。用户原本的麻烦正是固定阈值对不上素材，再留一套只会让两套语义打架。

---

## 前提与限制

* 自适应解决的是「阈值跟素材对不对得上」，**解决不了输入增益太小**。当前实测成片有效电平约 −29 dBFS，压完只是整体抬上来一点，听感离电台口播仍有距离。
* 要真正到位，需在 Windows 声音设置里把麦克风增益拧上去约 8 ~ 10 dB（WASAPI 共享模式下 Rust 侧改不了设备增益，见 AGENTS.md 硬约束 1）；调完增益重跑一次链路即可，链路的归一会自动重算。
* 自适应能保证的是：不管增益怎么拧、甚至换一支灵敏度完全不同的麦克风，压缩都不会压空。
* 「悦耳」还有两块没做：**齿音抑制**（电容麦近讲时 5 ~ 8 kHz 的齿音能量可能明显超出自身中位数，压缩与扩展都管不了音色）；**录音端的输入电平主动引导**（实时提示落在 −12 ~ −6 dBFS 目标带）。底噪是增益级配问题，链路末端只能按住、修不回来。

## 0.1.60 修订：门限锚点从「中位数」换成「噪声底」

上面第一版把剔除门限挂在「本段块电平中位数 − 20 dB」上，实测踩了两个坑，已改为挂在噪声底上：

* **中位数会随压缩移动**，而压缩就是这条链的一环 —— 压缩把语音压低十几 dB → 中位数与门限一起下降 → 原本被剔掉的气口重新进入统计，播报里于是出现「跨度 19.2 dB → 24.5 dB」这种「压缩后动态反而变大」的读数。
* **中等信噪比素材上气口落不进 −20 dB 的门限**（气口只比中位数低约 19 dB），气口被算成语音 → P10 等于气口电平 → 压缩阈值落在气口上、压缩比顶到 4:1，扩展器也因 headroom ≈ 0 恒跳过。

改用 `噪声底 + SPEECH_GATE_MARGIN_DB`（14 dB）后：噪声底是气口的电平、压缩在气口处增益≈0，不随压缩移动；它同时是绝对量，增益整体平移时判定不变。量压缩输出时再把**输入的**噪声底当锚传进去，前后才是同一批块。完整的问题描述、排查过程与验证数据见 [docs.md](../docs.md) 的「跨度门限锚点修复（0.1.60）」一节，未结的两项（余量取值要靠听感定、降噪的偶发高频爆点）见同文件「未结项（0.1.60 留待彻查）」。
